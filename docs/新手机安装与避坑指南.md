# 新手机安装与避坑指南

适用版本：定时打卡助手 0.2.2（构建号 11）。更新日期：2026-11-20。

按顺序完成本指南，再把手机放到现场运行。**手动打卡测试成功，不代表黑屏定时唤醒已经配置完成。** 这两部分必须分开测试。

## 1. 新手机需要满足什么条件

| 条件 | 具体要求 |
|---|---|
| 系统 | Android 6.0 或以上能够安装助手；不同机型仍须实测。当前验证机为 vivo X200s、Android 16、OriginOS 6；荣耀 8 尚需单独验收。 |
| 得力 e+ | 能正常安装、登录，账号属于正确组织，手动进入工作台和打卡流程正常。 |
| 锁屏 | 关闭锁屏密码、图案、PIN 等安全锁，可保留上滑进入。助手不会输入锁屏密码。 |
| 现场条件 | 手机实际放在允许打卡的地点，连接单位规定的 Wi-Fi，并允许得力所需的定位权限。 |
| 网络 | 得力能访问业务服务；若需要远程看日志，手机还须能够访问 `api.github.com`。 |
| 时间 | 开启自动校时并核对时间；计划统一按北京时间计算。 |
| 供电与后台 | 稳定供电，允许助手后台运行；关闭开发者选项中的“充电时保持唤醒／不锁定屏幕”。 |

日常运行不要求连接电脑、开启 USB 调试或 Root。USB 调试仅在电脑协助排查时使用。

## 2. 下载和安装

1. 从仓库下载 [daka-0.2.2.apk](../releases/daka-0.2.2.apk)。手机上下载的是 APK 安装包，不是整个源码压缩包。
2. 用文件管理器打开“下载／Download”中的安装包，按手机提示允许该来源安装。
3. 应用名称为“定时打卡助手”。vivo 安装时如要求验证手机账号，在手机上自行完成验证。
4. 新手机首次安装后打开助手，再配置权限和账号。

**覆盖升级时直接安装新版，不要先卸载。** 本次覆盖升级保留了已有设置、令牌和本地记录；卸载或清除应用数据会失去这些本地内容。

换新手机属于首次配置：账号、密码和 GitHub 令牌需要在新手机上重新填写，不会因为登录同一个 GitHub 仓库就自动恢复。不要直接复制旧手机的加密配置文件。

## 3. 开启助手需要的权限

打开助手底部“设置 → 环境检查与测试”，页面标题为“环境检查”。逐项完成：

| 功能 | 怎样设置 | 缺少时可能出现什么问题 |
|---|---|---|
| 无障碍服务 | 点击“打开无障碍设置”，开启“定时打卡助手”。若系统限制侧载应用，先在助手的系统应用详情中允许受限设置。 | 无法识别页面、点击、处理返回或解锁。 |
| 精确闹钟 | Android 12 及以上点击“允许精确闹钟”并授权；旧系统可能没有这一项。 | 无法可靠安排精确定时。 |
| 悬浮窗 | 点击“允许悬浮窗特殊访问”，开启助手权限。 | 部分系统可能阻止后台唤醒或拉起页面。 |
| 自启动、后台运行 | 在系统设置中允许助手开机启动和后台启动，允许后台运行。 | 重启后未恢复，或黑屏后不执行。 |
| 锁屏显示 | 厂商系统如有该项，开启助手的锁屏显示权限。 | 黑屏或锁屏状态下无法显示唤醒页。 |
| 后台弹出界面 | 厂商系统如有该项，开启助手的后台弹出界面权限。 | 能手动打开，但到点不能自动进入页面。 |
| 电池管理 | 将助手设为允许后台耗电、不限制或不优化等对应选项；正式使用时避免省电模式限制它。 | 延迟触发、后台被停掉或执行中断。 |
| 旧机主动熄屏 | Android 9 以下如不能主动熄屏，在助手中点击“激活旧系统主动熄屏权限”，激活设备管理。 | 结束后只能等待系统自动熄屏。 |

设备管理仅用于旧机熄屏；将来卸载前，先在助手中点击“取消设备管理激活（卸载前使用）”。

### vivo／OriginOS 6 的实测入口

进入系统：**应用信息 → 定时打卡助手 → 查看所有权限**，确认以下四项均开启：

- 自启动：包含开机启动、后台启动。
- 悬浮窗。
- 锁屏显示。
- 后台弹出界面。

本次黑屏故障排查时，悬浮窗已经开启，但另外三项全部关闭。手动打卡可以成功，黑屏唤醒仍然失败；手动开启三项并安装修正版后，十秒与两分钟黑屏唤醒测试均成功。

**不要看到“悬浮窗已开启”或助手“基础配置已就绪”，就认为厂商权限全部开好了。** 基础检查不能自动证明上述厂商开关已经开启。系统权限页的部分开关需要本人在手机上操作，电脑点击可能不生效。

荣耀／华为的入口和名称随系统版本不同，按相同功能寻找：自启动、后台运行、电池管理，以及锁屏显示／后台界面权限（如果系统提供）。没有某个同名开关时，用后面的黑屏测试验证实际能力，不照搬 vivo 的菜单位置。

## 4. 填写得力和远程日志设置

打开助手底部“设置”：

| 设置项 | 填写说明 |
|---|---|
| 目标应用 | 优先点击“从已安装应用选择得力 e+”。本次验证的包名为 `com.delicloud.app.smartoffice`。 |
| 组织全名 | 填得力工作台顶部的实际组织名称，文字必须完全一致。本次使用的是“数统803”。**这里不能填应用包名。** |
| 登录账号、密码 | 如需偶发掉线后自动登录，在本机填写。不要提交到仓库或放进公开日志。 |
| 打卡条件 | 默认等待指定打卡 Wi-Fi；只有单位确实使用 GPS 打卡规则时，才开启对应选项并在现场验证。 |
| 设备别名 | 每台手机使用独立别名，如 `honor8-main`。多台同时上报不能共用同一别名；产生记录后别名固定，首次保存前先确定。 |
| GitHub 仓库 | `sdhgdsfdusjdfs/daka`。 |
| 日志分支 | `device-logs`。不是默认源码分支 `main`。 |
| GitHub 令牌 | 在新手机上单独配置，仅授权本仓库的 Contents 读写权限。详见 [GitHub 日志配置](GitHub日志配置.md)。 |

填写后点“保存设置”。已有凭据留空保存会保留原值，清除要使用专门的清除按钮。

同一得力账号切换到另一台手机可能使原手机掉线。测试机和正式机交替登录后，要确认正式机仍能正常进入工作台。

点击“保存并测试 GitHub 连接与写入”确认远程配置。**电脑能通过 SSH 推代码，不代表手机已经配置好令牌。** 当前仓库公开，上传的运行日志也公开可见。

## 5. 设置实际执行时间

1. 在“计划”中增加或修改时间，核对上班／下班类型、星期和每条计划的启用状态。
2. 软件首次默认周一至周五：09:10 上班、11:35 下班、13:40 上班、18:05 下班。这只是默认值，按单位实际规则修改。
3. 可设置三个、四个或更多时间；同一天启用的计划至少间隔两分钟。
4. 核对“日期例外”，避免某天被设为停用。
5. 测试完成后开启首页总开关，确认显示“计划运行中”和正确的下一次任务时间。

改到今天已经过去的时间，不会立即补打一遍。超过计划时间一分钟才恢复的任务记为“错过”。节假日、调休需按实际规则设置日期例外。

## 6. 必须按这个顺序测试

| 顺序 | 操作 | 通过标准 |
|---|---|---|
| 1. 快速黑屏测试 | 在环境检查点“十秒后快速测试亮屏”，返回桌面并按电源键熄屏。 | 到点自行亮屏并解除无密码锁屏；回助手刷新后显示成功。不要提前手动点亮来代替自动唤醒。 |
| 2. 两分钟黑屏测试 | 点“两分钟后测试亮屏”，返回桌面、熄屏，等待。 | 等待期间保持黑屏，到点自行亮屏、解锁，测试结果成功。前两项均不会打开得力。 |
| 3. 打开和收尾 | 在环境检查点“测试打开并退到桌面”。 | 进入得力，缓冲后返回工作台大按钮页面、退到桌面并熄屏；查看最近退出及熄屏结果。此测试不点击打卡按钮，但得力自身可能自动打卡。 |
| 4. 现场真实测试 | 手机放到真实地点、接入指定网络，点“选择计划进行真实打卡测试”。 | 助手执行记录有本次成功时间，退出和熄屏结果正常，并与单位考勤记录一致。此项会执行真实打卡流程。 |
| 5. 黑屏定时整轮 | 设置一个符合单位规则、尚未到达的时间，启用计划，返回桌面并熄屏。 | 到点自动亮屏、解锁、打开得力，记录本次结果，再退后台、熄屏；核对本地和远程日志。 |

第 4 项通过不能替代第 1、2、5 项。手动测试时屏幕本来就亮着，会绕过最容易出问题的黑屏唤醒条件。

正式机还应核对全部实际时段，以及长时间熄屏／隔夜、重启后是否恢复。建议至少连续三个工作日核对 12 次计划；vivo 的测试结果不能代替荣耀 8 的实机验证。

## 7. 正常运行时会怎样

- 到点屏幕已亮且解锁：直接打开得力，不先熄屏。
- 到点黑屏或仍在无密码锁屏：先亮屏、解除锁屏，再打开得力。
- 启动后先缓冲约 8 秒，不增加广告跳过操作；期间仍观察短暂成功提示。
- 优先确认得力自动打卡结果，条件满足时再作一次备用按钮点击。明确的本次成功时间和正确组织才是成功依据，打开软件或点击按钮本身不算成功。
- 异常在原始一分钟窗口内最多尝试三次，共用剩余时间；剩余不足 19 秒不再新开尝试。本轮备用打卡按钮最多点击一次。
- 结束时先保存业务结果，再关闭成功提示、返回工作台大按钮页面、退到桌面并熄屏。页面收尾另限约 8 秒。
- 最终方案保留得力后台服务，不使用系统“强行停止”，也不依赖最近任务划卡。

打卡结果、返回工作台情况、熄屏情况和日志上传情况分开看。比如“成功但收尾未确认”不等于打卡失败。

## 8. 到哪里看记录

手机助手底部“记录”可按日期查看，点击单条记录能看执行过程。

GitHub 切换到 `device-logs` 分支，进入：

- `devices/设备别名/status.md`：最后上报、下一次任务、最近结果。
- `devices/设备别名/logs/README.md`：日期目录。
- `devices/设备别名/logs/YYYY-MM-DD.md`：当天记录，展开“执行过程”看异常和重试。

入口：[荣耀日志目录](https://github.com/sdhgdsfdusjdfs/daka/tree/device-logs/devices/honor8-main/logs) · [vivo 日志目录](https://github.com/sdhgdsfdusjdfs/daka/tree/device-logs/devices/vivo-test/logs)。

所有执行结果均自动排队上传，不只上传成功记录。网络不通时先保存在本地，恢复后补传。GitHub 页面需要刷新，旧的“已连接”不能证明手机当前在线；上报超过约 90 分钟未更新时应检查手机。旧月度文件仅作历史存档，新记录按天查看。

## 9. 我们踩过的坑和排查顺序

| 现象 | 优先检查 |
|---|---|
| 手动完整测试成功，黑屏时没有反应 | 先核对自启动、锁屏显示、后台弹出界面，再检查精确闹钟和无障碍；安装 0.2.2 或后续版本，重新做两种黑屏测试。 |
| 屏幕亮了，但没有进入得力 | 核对锁屏是否已解除、后台弹出界面权限、目标包名及无障碍连接；看执行步骤停在哪。 |
| 页面提示组织未核对 | 组织栏应填工作台顶部全名，不能填包名；账号登录到其他组织时也无法通过核对。 |
| 显示“外勤打卡”或未连接打卡 Wi-Fi | 检查实际地点、指定 Wi-Fi 和得力定位权限。该页面不能当作正常现场打卡已经通过。 |
| 已点按钮但“结果未知” | 查看本次成功回执和单位考勤记录；点击动作不等于服务器确认成功，不要靠重复点按钮判断。 |
| 到点很久以后才执行，显示“错过” | 检查自启动、后台耗电限制、精确闹钟和是否被强制停止；再测试黑屏等待与隔夜执行。 |
| 熄屏后下一次不能唤醒 | 先确认无密码锁屏与厂商后台权限；旧机另测设备管理熄屏后能否再次唤醒。 |
| 令牌填了却报 404 | 使用新版；旧版连接测试曾因接口地址尾斜杠误报 404。新版仍报错时核对仓库、`device-logs` 分支及令牌授权。 |
| 电脑仓库更新了，手机没有日志 | 手机要独立配置令牌并能访问 GitHub API，查看待同步数量和同步错误。 |
| 在 main 分支找不到日期日志 | 运行日志在 `device-logs` 分支；按设备别名和日期进入。 |
| 升级后权限失效或服务未连接 | 重新打开助手，核对无障碍、定时、厂商后台权限和下一次任务，再做黑屏测试。 |

完成配置后，保留助手后台运行，避免对助手使用强行停止、清除数据或系统后台清理。若已被强行停止，先重新打开助手恢复调度。重启、升级或更换得力版本后，也应重新确认权限与实际流程。

## 10. 放到现场前最后检查

- [ ] 已安装当前版本；得力登录、组织和指定网络正常。
- [ ] 无密码锁屏；充电时保持唤醒已关闭；时间准确。
- [ ] 无障碍、精确闹钟、悬浮窗和厂商后台权限逐项核对。
- [ ] 快速与两分钟黑屏测试都成功。
- [ ] 真实打卡、收尾、熄屏和黑屏定时整轮均核对。
- [ ] 每条时间、星期、日期例外和首页总开关正确，下一次任务正确。
- [ ] 新手机设备别名独立；GitHub 令牌已配置，远程日志能刷新看到。
- [ ] 已核对单位考勤记录，并保留初期人工检查。
