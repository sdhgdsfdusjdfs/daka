# 手机安装与配置

## 安装

将 `releases/daka-0.1.0.apk` 传到手机，用文件管理器打开安装。工具显示为“定时打卡助手”。允许来源安装后，按系统提示完成安装。

正式运行使用荣耀 8；vivo X200s 用于初期验证。两台手机均由用户先确认能正常安装、登录得力 e+。工具最低 Android 版本为 6.0，旧系统的实际后台运行行为仍需验证。

## 基础设置

1. 手机使用无密码锁屏，可保留上滑进入。保持供电，关闭“充电时屏幕保持唤醒”的开发者选项。
2. 保持系统日期时间准确，工具按 `Asia/Shanghai` 调度。
3. 得力 e+ 连接实际打卡地点的指定网络，授予其所需定位权限。
4. 打开工具的“设置应用、登录和 GitHub”。从已安装应用选择得力 e+，填写工作台顶部组织名称，必须与页面文字完全一致。
5. 配置账号密码以供偶发登录失效时使用。留空保存会保留已有凭据，可用专门按钮清除。
6. vivo 使用设备别名 `vivo-test`，荣耀使用 `honor8-main`。产生记录后别名固定。
7. 默认备用按钮点击要求看到“已连接打卡 Wi-Fi”。如果单位使用 GPS 规则，在设置中明确开启相应选项，并在现场验证。

## 系统权限

进入“环境检查与权限”，逐项完成：

- 无障碍服务。Android 新版本的侧载应用可能需要先到应用详情允许受限设置。
- Android 12 及以上的精确闹钟访问。
- 现代系统如阻止后台拉起，可开启悬浮窗特殊访问并实测。
- 系统中的自启动、后台运行和电池优化例外。不同 EMUI／OriginOS 版本入口不同，以手机界面为准。
- 荣耀旧系统如需主动熄屏，激活本工具的设备管理权限，仅用于强制锁屏／熄屏。卸载前可在工具里取消激活。

“基础配置就绪”只表示所检查的权限与配置存在。必须完成下面的实际测试才能确认能力。

## 测试顺序

1. 点击“两分钟后测试亮屏”，返回桌面并让手机熄屏。
2. 两分钟后应点亮并解除无密码锁屏，工具记录具体结果。此测试不会启动得力 e+。
3. 确认会产生真实考勤记录后，选择“真实打卡测试”。目标 App 可能在打开时自动提交。
4. 观察本地记录是否保存本次成功时间、组织核对结果及熄屏状态。
5. 在日常用手机刷新 GitHub 状态页确认同步。
6. 核对四个实际时段与单位考勤记录的归属，连续验收后才依赖无人值守。

如看到“页面需要适配”“协议勾选框无法识别”“组织未核对”，将本地执行步骤和对应页面提供给开发人员。当前文本规则来自用户录屏，控件结构需要实机验证，程序会停下并留下结果。

如需协助适配，在“环境检查”选择“五秒后采集目标页面结构”，切到目标页面等待，然后回工具选择“查看／分享最近采集的页面结构”。采集结果保留控件 ID、边界和指定标签，其他文本以长度替代。成功提示页需要尽量在采集时间内保持可见。今日记录后备判定要求可核对完整日期，缺少日期时以本次成功回执为主。

## 时间和日期例外

时间编辑可增加、删除、暂停计划，每条可独立选择星期，启用计划至少间隔两分钟。日期例外可以停用一天，或选择当天执行的已有计划，优先于星期规则。需要启用的计划本身也应处于启用状态。

修改时间保存后重排未来任务。修改到今天已过去的时间，从下一个有效日期执行。暂停计划会取消未来打卡闹钟，已经发给目标 App 的提交无法撤回。

## 运行结果

- 成功：本次成功回执或今日记录被确认，业务班次仍以单位报表为准。
- 结果未知：App 可能已提交，但工具未取得充分证据。请人工核对，工具不会盲目反复点击。
- 失败：权限、登录、启动、页面或现场条件阻止本轮完成。
- 条件不满足：已识别到外勤页面、指定网络未连接或现场定位条件未满足，需到实际地点再验证。
- 错过：超过计划时间一分钟才恢复执行。

任务日志上传失败和打卡结果独立保存。断网后记录在本地保留，网络恢复后再同步。保持工具启用；系统“强制停止”后，需要重新打开工具恢复调度。
